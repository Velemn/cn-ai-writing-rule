# 附录 A：项目专属规则库

只读取与当前任务相匹配的项目章节。本文件中的企业、章节、字体、数据、文件名和业务字段不得并入通用规则。如当前用户提供了较新的明确要求，以较新要求为准。

## A1. 《选题4：自动化审计工具研究》逻辑框架图

1. 采用纵向布局、黑框白底、正常学术风格，主要研究阶段以自上而下的箭头连接。
2. 不设左侧“采购到付款/P2P贯穿场景”独立栏，不设右侧“IT审计关注点”独立栏，不在底部设“数据引用策略”等补充区。
3. 当前可保留的主干为“行业痛点—工具现状—场景适配—价值与局限—AI趋势—审计视角升华—结论与建议”。

## A2. IT Audit 比赛共同知识库

1. 共同底座使用 Markdown，作为三名成员首次提供给各自 AI 的统一背景文件。
2. 共同说明文件只写比赛定位、比赛介绍、IT/IT Audit 介绍和输出规范；不写固定成员分工和时间安排。
3. 三人共同推进同一方案，不在开始阶段切成互不相关的模块。主力/辅助是动态状态，不是永久角色。
4. 每份共享文件必须独立可读，使其他成员和 AI 理解“文件是什么、已写了什么、下一步做什么”。
5. 知识库可从“企业信息系统与业务流程”开始，不为形式完整强制按章节顺序搭建。
6. “正式赛题公布前不押题”是已过期的阶段性规则，不自动延续。

## A3. IT Audit 赛道三：第三方 IT 风险审计

1. 统一使用“第三方服务审计”“第三方服务商审计”或“第三方IT风险审计”，不使用“第三方服务费审计”。
2. 以 `002` 为唯一内容母版，`001` 只吸收表达与 PPT 施工优势。
3. 以“控制边界外移”为总主轴；连锁零售是承载业务场景，不写成行业研究报告。
4. 权限配置审计作为最深场景，保留可执行审计程序。
5. AI、第 N 方与 Shadow AI 是前沿增量，不压过第三方服务商风险管理主线。
6. 不虚构企业经营数据；AI 厂商能力和案例数字在核验完成前保持“待核验”。

## A4. IT Audit 赛道六：云环境审计

1. 以 `001` 为内容母版，`002` 用于 PPT 降噪与表达压缩。
2. CAM-CC 是核心方法论，不压缩为附带图表。
3. 工具章回答“审计证据从哪里来”，不写成 AWS、Azure 或阿里云产品介绍。
4. KPMG 数据只保留少数关键证据，不将官方材料堆成背景综述。不以 SOX 为作品主线，不使用“超越 KPMG”类定位。
5. 中国监管要求用于证明本地适用性，不独立发展为法规综述。
6. 完整母版可保留深度，正式展示稿再独立压缩；15–18 页是该阶段的项目规则。

## A5. 企业财务业务流程—附件票据模型

1. 不再以原 19 个场景作为最终一级框架，改按企业实际业务大类和财务事件组织。
2. 核心字段为“业务大类、具体业务流程/财务事件、内部需填制单据、外部取得/第三方单据”。
3. 只保留与财务相关且通常形成单据的事件，不列完整经营操作链。
4. 采购类至少可区分请购、验收入库、支付货款、领料出库；员工出差区分出差申请、出差借款、差旅费报销；费用付款单独识别“费用支付申请”。
5. 新模型遇到初始对照表中已有票据时，沿用完整正式名称和括号备注。每次重构后做原票据覆盖检查。
6. Excel 单元格多项内容使用“1. 2. 3. + 换行”，不使用圈号数字；延续既有表格视觉风格，不为整齐强制统一条目数。

## A6. 财务科目附件规则配置

1. 规则表包含“财务科目、现有附件清单、真实业务场景判断、所有可能附件审查结果、必要性文件审查结果、系统配置优化建议”。
2. 每个科目检查现有附件是否符合真实流程、是否遗漏常见附件、哪些不应强制、是否需按场景拆分。
3. 附件分为必备、辅助、可选；不将理论上可能但实际少见、系统难取得的材料默认必填。
4. 销售费用、管理费用、营业外支出、财务费用、税金及附加等大类先拆业务小类。
5. 税费区分计提与缴纳；收入类不只看发票，按合同、履约、验收、开票、收款等阶段判断。
6. 讨论 OA 审批记录是否作为电子原始凭证进入附件体系。如关键信息已在综合文件中，说明需提取的字段，不只写“上传合同”。
7. 系统落地规则说明字段、触发条件、必填条件与不宜强制的内容，服务于凭证附件、原始凭证管理和附件校验配置。

## A7. Velemn 业财融合/财务共享平台

1. 项目角色是“产品试用 + 财务规则审查 + 需求梳理 + 功能优化建议”，不写成参与系统开发。
2. 系统主链路为“OA/业务系统 → CDM/数据湖采集、治理、标准化 → 财务共享中心 → 会计确认与凭证 → 账簿 → 报表/分析”；不简化为“从 OA 直接拿数”。
3. 优先使用“会计科目”“科目汇总表”等规范名称。
4. 核心分析对象是业务事件向财务结果的自动转换，包括科目、摘要、借贷、附件、审核、报表和追溯。
5. 平台能力区分“已实现、存在 Bug、开发中、未来规划”，不将目标架构写成当前能力。
6. 现有资料更支持“基础核算链路/财务共享雏形”的谨慎判断，不直接夸大为成熟的“业财一体平台”。

## A8. 联合电服数据资产会计信息研究报告

### 主线与章节边界

1. 全文围绕“经济高质量发展需求牵引数据资产会计信息供给—高质量会计信息反向支撑/赋能经济高质量发展”的双向机制展开，不缩减为“数据资产入表”。
2. 第一至第三章保持理论、制度与一般机制分析；联合电服的公司名称、业务数据和详细实践集中于第四章。
3. 第三章可按“需求牵引—制度转化—业务基础—合规确权—会计信息生成—质量保障”解释供给形成，以“微观—中观—宏观—综合效应”展开实现路径。
4. 第四章五个部分严格分工：（一）企业背景与实践基础；（二）数据资产会计信息形成与供给；（三）交易、评估、质押融资与再投入的价值验证；（四）企业、行业、公共治理、跨行业的高质量发展实现路径；（五）案例启示与边界反思。
5. 第四章（四）不重复数据治理、资产确认计量、部门职责、交易评估融资过程和产品功能清单。第四章（五）不再完整罗列案例数据。
6. 第五章政策建议回应前文已识别的现实问题，不重新介绍案例或生成通用建议。

### 机制与案例使用

7. 企业微观路径同时覆盖价值创造、融资优化与治理提升，并吸收“数据资源—数据产品—数据资产—融资—再开发”循环，但在理论章保持抽象。
8. 中观路径重点说明统一、可信、可比较的价值表达如何支撑交易、协同、价值发现、外部验证、信用形成、专业分工与可复制管理范式，不停留于机构清单或“降低信息不对称”。
9. 宏观路径联系数字经济核算、运行监测、全要素生产率识别、公共服务绩效和政策量化依据，不泛泛写“提升治理能力”。
10. 综合效应可按“价值显化—信任传递—资源引导—循环优化”连续传导，回扣“需求牵引—供给响应—价值实现—反馈优化”。
11. 主体报告中的全生命周期管理、作业成本法、多维估值模型、业财数融合和价值闭环必须进入实际分析环节，不只列名称。
12. 写入表时联系作业成本法与成本归集；写评估融资时区分成本法、市场法、收益法的信息功能；写持续迭代时联系全生命周期管理；写治理优化时联系业财数融合。

### 资料、数据与文献

13. 新提纲控制章节功能；去年原版校准理论骨架；主体报告提供企业实践、管理会计方法与价值链；现有正文用于控制重复；其他案例资料用于事实和数据核验。
14. 正文不使用“主题报告”作为来源称谓，也不以“去年原版中”等表达暴露底稿分工；将材料内容吸收进论证。
15. 项目文献只使用用户提供或已在项目修改稿中确认的文献，不自行新增外部文献。
16. 文中与文后文献同步；项目格式示例为 `[1]秦书生,温佩莹.经济高质量发展内涵的多维阐释[J].当代经济研究,2025,(8):26-36.`，使用半角标点。
17. 严格区分入表金额、评估价值、授信额度、质押融资额、实际提款、合同金额、交易登记金额，并区分 53/62 个产品、500 万/近 1000 万元入表金额等不同时点与口径。
18. “评估价值超过 3000 万元、质押融资近 2000 万元”可用于企业价值与信用验证；“六大产品线、62 个数据产品”可用于行业产品化基础；公共治理结果数据使用后必须紧接解释治理意义。使用前仍需核对当前材料版本。
19. 客户、合同、证书、系统截图与内部业务资料进入正式文本前检查公开边界并脱敏。

### 项目语言与协作

20. 企业首次出现使用“广东联合电子服务股份有限公司（简称‘联合电服’）”；第四章（一）段首仍使用企业全称。
21. 正文尽量不使用“本研究、本案例、前文、本小节”等元语言；结论中确需回扣证据时可有限使用明确对象的表达。
22. 其他成员已完成的第二章及相关分稿以其最新修改稿为主，只做必要语言优化、衔接与事实纠正，不整体重构。

# 规则优先级、频率与冲突处理

## 证据基础

本 Skill 依据当前文件夹中 `1.md`—`29.md` 的写作规则总结建立。`5.md` 与 `8.md` 内容完全相同，`6.md` 与 `9.md` 内容完全相同；频率判断时各只计一次，因此使用 27 份独立总结。

规则只有在下列情况下进入通用核心：

1. 多份独立总结反复出现；
2. 某份总结保留了清晰的用户明确指令；
3. 规则可以脱离某一项目的企业、章节、字体、数据与文件名仍然成立。

仅有【行为推断】且未经多份总结印证的内容，不设为强制规则。

## 高频主题审计

下表的数字是“27 份独立总结中明确提及该主题的文件数”，用于识别重复性，不代表每份文件对其强度完全一致。

| 主题 | 提及文件数 | 级别判断 |
| --- | ---: | --- |
| 段首句 | 26/27 | 一级 |
| 反对机械三段式/固定段数 | 25/27 | 一级 |
| 案例必须进入机制分析 | 23/27 | 一级 |
| 保持既定框架或标题边界 | 22/27 | 一级 |
| 专业性不来自术语堆积 | 21/27 | 一级 |
| 避免 AI 高频对举句 | 20/27 | 一级 |
| 明确章节功能 | 18/27 | 一级 |
| 修改后再次自审 | 17/27 | 一级 |
| 修改前读原稿/意见/材料，先审查 | 17/27 | 一级 |
| 区分数据口径与时点 | 16/27 | 一级 |
| 不编造或补齐事实 | 15/27 | 一级 |

敏感信息与脱敏在很多总结中出现，但部分文件只是说明“本轮未涉及”，因此不用简单关键词统计它的准确频次。其明确要求足以作为对外正式文本的场景规则。

## 冲突表

| 规则A | 规则B | 来源情况 | 建议保留 | 判断理由 |
| --- | --- | --- | --- | --- |
| 既定框架不得擅改 | 整体方向错误时应重建结构 | 两者均有明确或多次反馈；后者多出现于用户明确否定建模对象时 | 两者均保留 | 默认保留框架；用户明确否定整体方向或授权重构时才重建。 |
| 采用“讨论—小步修改—反馈” | 直接交付完整稿/完整文件 | 前者在审查和逻辑未稳定阶段多次出现；后者是后续的明确任务要求 | 两者均保留 | 工作模式由当前动词决定：“审查/讨论”先诊断，“给完整稿”直接交付。 |
| 不使用“前文、本研究、本案例” | 总结章有时接受“前述实践”回扣证据 | 早期有明确禁用；后续在高层次提炼中出现接受案例 | 保留“默认避免，文体需要时有限使用” | 反感的是模板化导航，而非所有交叉引用功能。 |
| 数据融入不足，需增加证据 | 已出现的数据不要在后续重复 | 前者是前端论证的明确反馈；后者是后续总结章的较新要求 | 两者均保留 | 首次承担证明功能时充分展开；后续只保留证据锚点或承担新分析功能。 |
| 内容应简洁、压缩 | 核心机制不能只写一点点 | 两类反馈都多次出现 | 两者均保留 | 压缩重复、背景、口号与无功能材料；保留必要的中间机制、证据和条件。 |
| 理论章保持抽象 | 案例必须详细介绍业务过程 | 两者均是多次明确要求，但适用章节不同 | 两者均保留 | 理论章提炼一般机制；案例章保留足以说明作用逻辑的业务细节。 |
| 资料冲突时保留差异，不择一 | 优先采用较新、权威的用户材料 | 前者是多份总结的强规则；后者在特定项目中出现 | 保留核查流程，限制自动覆盖 | 先核查时间、口径和确认状态；只有较新版被明确确认为替代版本时才覆盖。 |
| 一个重要三级标题下不宜只有一段 | 段落数量不设固定标准 | 前者出现于部分明确反馈；后者几乎贯穿全部来源 | 保留后者为主，吸收前者的条件 | 如果一段无法完成该标题的实质论证才拆分，不将“至少两段”设为通用模板。 |
| 标题可以有趣、有记忆点 | 既定标题不得擅改 | 前者来自 IT 审计方案设计；后者是多项目高频规则 | 保留后者为优先 | 只在新建标题且文体允许时考虑记忆点；已定标题不因润色改名。 |
| 摘要应压缩 | 摘要应恢复较完整版本 | 前后任务中出现明确变化 | 不设通用长度 | 摘要篇幅依当前明确要求和文件功能决定，核心论证不受机械页数目标挤压。 |
| 页码暂不检查 | 目录页码必须逐项核对 | 两次任务检查范围不同 | 按当前任务范围保留 | “暂不检查”不是永久排版偏好；正式定稿要求核对时，以最终文件为准。 |

## 不得泛化的内容

下列信息不进入通用规则，只能在适用项目中启用：

- 联合电服报告的固定章节分工、双向机制、企业名称、金额与产品数据；
- 联合电服的方正小标宋、黑体、楷体_GB2312、仿宋_GB2312、字号、目录、页码、续表和文献标点格式；
- IT 审计赛道的母版选择、CAM-CC、页数、赛题和标题方向；
- 财务附件/票据模型的固定字段、科目分类、票据名称与系统配置规则；
- 共同知识库的 Markdown 底座、成员分工、赛题预测与文件范围；
- 某份文件中的图表视觉风格、箭头、布局与被删除模块；
- 任何项目特定的文献来源限制、证据排名或企业内部资料口径。
